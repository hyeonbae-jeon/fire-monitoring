# Windows 실행 패키지 사용방법

대상: Windows 10/11 64비트(x64) PC. Git, .NET, Node.js를 설치하지 않아도 됩니다.
ZIP 안에 .NET 런타임과 웹앱이 포함되어 있으며 실행 시 다운로드하지 않습니다.

## 실행

GitHub Actions에서 다운로드할 경우 GitHub에 로그인한 뒤 실행 결과의
`Windows-Camera-Inventory-Demo` 아티팩트를 클릭하세요.
아티팩트 ZIP을 먼저 풀면 실행 패키지 ZIP과 SHA256 파일이 나오며, 실행 패키지 ZIP도 풀어야 합니다.
아티팩트는 30일 동안 보관됩니다. 만료되면 workflow를 다시 실행해 새 파일을 만들 수 있습니다.

기존 버전에서 새 지도 영상 패널로 업데이트할 때는 캡처 도구에서 **수집 중지** 후 도구를 닫고,
Bridge 콘솔도 닫습니다. 새 패키지는 별도 폴더에 풀어 기존 설정 폴더를 보관하세요.
새 폴더의 실행파일과 화면캡처.cmd를 다시 실행하고 새로 열린 로컬 브라우저를 사용합니다.

1. ZIP 파일을 회사 PC로 가져가 전체 압축을 풉니다. ZIP 안에서 바로 실행하지 마세요.
2. 압축을 푼 폴더의 `WisenetPtzBridge.exe`를 더블클릭합니다.
3. 콘솔 창과 기본 브라우저가 열립니다. 콘솔 창을 닫으면 서버도 종료됩니다.
4. 샘플 카메라를 선택하고 웹 화면의 저장 키에 `local-demo-only`를 입력합니다.
5. '선택한 카메라 저장'을 누르면 같은 폴더의 `data/cameras.demo.json`에 저장됩니다.
6. 종료 후 다시 실행하여 선택이 유지되는지 확인합니다.

저장 키는 공개된 로컬 샘플 전용 값이며 운영 비밀번호가 아닙니다.
브라우저가 열리지 않으면 콘솔의 `Browser:` 옆 주소를 복사하여 주소창에 입력하세요.
포트는 자동으로 선택되므로 실행할 때마다 주소가 바뀔 수 있습니다.
PC 밖에서 접속할 수 없도록 루프백 주소에만 바인딩합니다.

## 이번에 테스트할 수 있는 것

- 샘플 이름/UUID/PTZ capability 조회, UNKNOWN과 없음 구분
- 검색, 여러 카메라 선택, 중앙 설정 저장
- 프로그램을 종료하고 다시 실행했을 때 선택 유지
- 참조 화면과 VWorld 가상 시점 비교, 추정 방향·기준점 기록 및 지도 설정 재시작 유지
- SSM 영상이 표시되는 동일 PC에서 영상 영역을 읽기 전용 수집하고 브라우저의 실시간 화면 시험 탭에서 확인
- 접근 권한이 있는 네트워크에서 한화 카메라의 JPEG 영상을 직접 수신하고 기존 영상 방향 추정 시험에 전달

**Wisenet SSM에 실제로 연결하지 않습니다.** 회사 PC에 Wisenet 프로그램이 있어도 자동으로
카메라를 읽지 않습니다. `demo/inventory.json`은 합성 샘플이며 실제 장비 목록이 아닙니다.
PTZ 제어/구독 및 RTSP 스트림 수신은 포함하지 않습니다. 한화 JPEG 직접 수신 시험과 선택한 SSM 영상 영역의 화면 수집은 별도로 선택합니다.
VWorld 위치 시안은 지도 모니터링 탭에서 확인합니다. 운영 환경변수나 SSM 비밀번호도
사용하지 않습니다. 운영 설정과 별도의 data/cameras.demo.json 및 data/map.demo.json을 사용합니다.

실제 전체 SSM 목록 연결은 외부 조회 인터페이스의 인증/UUID/필드/페이지 처리 확인이 선행되어야 합니다.
이번 실행 패키지는 설치 없이 UI와 저장 기능을 시험하기 위한 버전입니다.

## 장비 값으로 지도 시점 따라가기

직접 JPEG/PTZ 수신 후 **지도 모니터링 → 실시간 영상 → 지도 추종 방식 → 장비 PTZ 근사 추종**을 선택하세요.
현재 CCTV에 맞출 방위각·기울기·화각·렌즈 높이를 입력하고 같은 카메라임을 확인한 뒤 **현재 PTZ를 기준으로 시험 추종 시작**을 누릅니다.
정밀 지형 정합 없이 Pan/Tilt 변화와 선택적 Zoom 배율을 지도에 근사 반영합니다. 설치 좌표는 바꾸지 않습니다.
동작 확인 후 **근사 기준을 지도 설정에 반영 → 카메라·설정 → 중앙 지도 설정 저장**으로 보관하세요. 재실행 후 같은 카메라에 연결하고 **저장 기준으로 추종 재개**를 누릅니다. JSON 다운로드·불러오기로도 카메라별 기준을 옮길 수 있습니다. 영상 패널의 **추종할 설치 카메라**에서 카메라를 전환합니다.
이 기능은 최신 로컬 실행 패키지에서 사용하며 공개 Pages의 사진 보정과 구분합니다. 사용 범위와 종료 조건은 [영상/장비 추종](visual-tracking.md#장비-ptz-근사-추종으로-진행)을 참고하세요.

## SSM 실시간 화면 수집 시험

SSM에서 한 카메라를 크게 표시하고 같은 PC에서 `화면캡처.cmd`를 실행합니다.
영상 영역을 선택하고 도구 창을 영상과 겹치지 않게 옮긴 뒤 수집을 시작하세요.
브라우저에서 **실시간 화면 시험 → 라이브 화면 확인**을 선택합니다. 조회 키는 자동 입력됩니다.
최신 패키지에서는 **지도 모니터링 → 실시간 영상 → 지도에서 라이브 확인**으로 지도와 영상을 함께 볼 수도 있습니다.
이 패널은 로컬 실행 브라우저에서 사용하며 공개 Pages에는 표시하지 않습니다. 선택한 지도 위치와 영상의 장비 일치는 별도로 확인하세요.
수집 도구의 방향은 UNKNOWN입니다. 최신 로컬 지도 패널에서는 별도로 **영상 방향 추정 시험**을 시작하고, 검증된 영상 대응에 한해 지도 시점 자동 갱신을 켤 수 있습니다. 실제 방향 정확도는 미검증입니다. [원본 사진·시안 JSON 준비와 시험 순서](visual-tracking.md).
상세 실행·중지·검은 화면 확인·시험 결과 위치: [docs/screen-capture.md](screen-capture.md).

## 한화 카메라 JPEG 직접 수신 시험

1. 카메라 웹뷰어에 접속 가능한 PC에서 패키지를 실행합니다. Wisenet SSM과 화면캡처.cmd는 실행하지 않아도 됩니다.
2. **지도 모니터링 → 실시간 영상 → 영상 입력 방식 → 한화 카메라 직접 수신**을 선택합니다.
3. 카메라 이름, **카메라 웹 접속 주소**, 장비 ID/PW를 입력합니다. DDNS로 접속한 경우 브라우저에 최종 표시된 장비 주소를 복사합니다.
   `/wmf/index.html#/uni/channel`이 붙은 최종 주소도 입력할 수 있습니다. 실제 주소·계정은 채팅이나 GitHub로 보내지 않습니다.
4. **JPEG 연결 시험·수신 시작**을 누릅니다. 기본 시험 경로는 `/stw-cgi/video.cgi?msubmenu=snapshot&action=view&Profile=1` 한 개입니다.
   2026-10-22 사용자 PC의 숨은벽 XNP-6550RH에서 직접 영상과 수신 장수·시각의 지속 갱신을 확인했습니다. 다른 장비/펌웨어/권한에서는 별도 시험이 필요합니다. 웹뷰어의 PNG 저장 성공만으로 JPEG API 지원을 판단하지 않습니다.
   확인한 JPEG 주소를 직접 입력할 수도 있지만 snapshot/view 조회와 숫자 Channel/Profile 외의 요청은 거절합니다. DDNS 이동·여러 경로·다른 포트 자동 시험은 하지 않습니다.
5. 영상과 수신 장수·시각이 갱신되는지 확인합니다. 성공한 직접 영상은 기존 **영상 방향 추정 시험**으로 전달되며 카메라 일치 확인과 기준 사진·보정 시안은 여전히 필요합니다.
6. **직접 연결 종료**로 수신을 중지합니다. 영상 조회가 약 15초간 없으면 자동 종료합니다. 일반 수신의 계정과 JPEG는 서버 메모리에서만 유지하고 로그·브라우저 저장소에 남기지 않습니다. 운영자가 선택한 참조 이미지·기준 묶음 다운로드는 아래와 같이 별도로 저장합니다.
   프로그램 재시작 또는 연결 종료 후에는 계정을 다시 입력합니다. 한 번에 한 대의 JPEG 수신을 시험합니다.

카메라로는 GET 요청만 보내며 HTTP Digest, 또는 정상 인증서의 HTTPS에서 Digest/Basic을 협상합니다.
인증·접근 거절, 잘못된 이미지, 타임아웃과 네트워크 오류 시 과거 영상을 지우고 자동 재인증을 반복하지 않습니다.
HTTP Basic으로의 폴백, 인증서 검증 해제, 카메라 PTZ/설정 변경과 외부 분석 서버 전송은 추가하지 않습니다.
수신 시각은 PC의 응답 수신 시각이며 센서 촬영 시각 또는 원본 영상의 멈춤 여부는 미검증입니다.
공개 Pages에서는 이 기능을 제공하지 않습니다. 일반 Bridge는 기본 비활성이고 `DIRECT_CAMERA_SNAPSHOT_ENABLED=true`와 `CAPTURE_READ_KEY`가 있어도 localhost 요청만 받습니다.

### 장비 Pan·Tilt·Zoom 자동 조회

연결 전에 **장비 Pan·Tilt·Zoom 함께 조회**를 체크하고 **JPEG 연결 시험·수신 시작**을 누릅니다.
같은 장비 주소·메모리의 인증 연결로 아래 GET 한 개만 약 1초 간격 조회합니다.

`/stw-cgi/ptzcontrol.cgi?msubmenu=query&action=view&Query=Pan,Tilt,Zoom`

사용자가 2026-10-22 숨은벽에서 이 경로의 Pan/Tilt/Zoom/ZoomPulse와 Channel.0 값 반환을 확인했습니다.
이번 패키지는 그 조회를 자동화하며, 사용자 PC에서 자동 PTZ 값의 지속 갱신도 확인했습니다.
Channel 0 또는 채널을 생략한 단일 카메라 JPEG에만 연결합니다. 회전·줌 명령이나 설정 변경은 보내지 않습니다.

**장비 PTZ 수신 상태**에서 원시 값, 수신 횟수와 시각을 확인합니다. 0도와 ZoomPulse 0도 유효한 값입니다.
604 오류·누락·비수치·중복·채널 값 불일치, 권한/네트워크 오류는 미확인으로 처리하고 각도 조회를 중단합니다.
JPEG 수신은 독립적으로 계속하며, 각도 재조회는 직접 연결 종료 후 다시 시작합니다. 4초 지난 값은 표시하지 않습니다.
직접 연결 종료·15초 영상 조회 부재·영상 수신 실패 시 각도 조회도 정리하며 이전 연결의 응답을 재사용하지 않습니다.

**Pan은 지리적 방위각이 아니고 Zoom은 수평 화각이 아닙니다.** 현재는 지도 자동 갱신에 사용하지 않습니다.
다음 단계는 영상의 지형 기준으로 설치 방위 오프셋·기울기 기준·줌별 화각을 보정한 뒤 다른 방향에서 검증하는 것입니다.
과거 사진의 지도 방위각과 다른 시각의 장비 Pan을 한 쌍으로 묶으면 안 됩니다. 사진과 PTZ는 별도 조회이며 두 수신 시각도 촬영 동시성을 보장하지 않습니다.
일반 조회값은 메모리에서만 처리하며 지도 설정에 저장하지 않습니다. 사용자가 선택한 기준 묶음 다운로드는 아래 절차로 별도 저장합니다. `directionStatus: unknown`은 지리적 방향 미보정 상태입니다.

### 영상·PTZ 기준 묶음 저장

직접 영상과 장비 값이 정상 수신 중이면 **영상·PTZ 기준 묶음 저장**을 사용할 수 있습니다.
같은 장비 연결과 JPEG 프로필로 **PTZ 조회 → JPEG 요청 → PTZ 재조회**를 차례로 실행하고 ZIP 하나를 다운로드합니다.
웹뷰어 PNG와 직접 JPEG를 섞거나 각도 값을 별도로 옮겨 적을 때 생길 수 있는 영상 프로필·수신 시각 차이를 줄이는 기능입니다.

1. 장비 PTZ 조회를 켜고, 카메라가 멈춰 값이 안정된 상태에서 **영상·PTZ 기준 묶음 저장**을 누릅니다.
2. 같은 줌에서 공통 지형이 보이는 다른 시점을 잡고 값이 안정되면 같은 버튼으로 두 번째 ZIP을 저장합니다.
3. 두 ZIP은 `reference.jpg` 원본과 `reference-metadata.private.json`을 각각 포함합니다. 파일을 다시 캡처하거나 자르지 않고 분석에 사용합니다.

메타데이터는 이미지 SHA-256·크기, 운영자가 입력한 카메라 이름·세션 식별자, 숫자 Channel/Profile,
저장 전후 Pan/Tilt/Zoom/ZoomPulse와 각 요청·수신 시각을 기록합니다. 장비 주소·ID/PW·쿠키·조회 키는 넣지 않습니다.
실제 영상과 장비 값이 들어 있는 운영 자료이며 지도 설정 불러오기용 JSON과 다릅니다.
서버는 ZIP을 파일로 보관하지 않고 메모리에서 만들어 운영자가 요청한 브라우저 다운로드로만 반환합니다.

Pan/Tilt 차이가 각각 0.1°를 넘거나 Zoom 차이가 0.0001을 넘거나 ZoomPulse가 달라지면 저장하지 않습니다.
한 번에 한 묶음만 만들고 전체 수신은 최대 8초로 제한합니다. 연결 종료·교체·화면 표시 중지 시 진행 중인 저장은 취소합니다.
영상의 일반 수신과 지도 설정은 이 저장으로 바꾸지 않습니다.
이것은 JPEG 요청 전후의 장비 값 확인이며 센서 촬영 시각의 하드웨어 동기화가 아닙니다.
중간에 움직였다가 같은 값으로 돌아온 경우나 원본 영상이 멈춘 경우는 판별하지 못합니다.

## NVT STH775 JPEG 직접 수신

NVT 웹뷰어가 사용하는 **GET `/cgi-bin/GetImage.cgi`**를 선택한 한 장비에서 조회합니다.
사용자 PC에서 이 방식의 영상 수신·장수·시각 갱신을 확인했습니다.
현재 PTZ 자동 조회는 아래 Position OSD 원본의 읽기 요청으로 추가했으며 실제 장비 수신은 새 패키지로 확인합니다.

1. **실시간 영상 → 영상 입력 방식 → NVT STH775 직접 수신**을 선택합니다.
2. 카메라 이름을 확인하고, 웹뷰어 Network에서 복사한 **NVT JPEG 요청 전체 주소**를 붙여넣습니다.
   최종 장비의 `/cgi-bin/GetImage.cgi`와 `USER`, `PWD`, `InputNumber=1`, 선택 `time`이 포함된 주소입니다.
   주소 속 PWD는 웹뷰어가 만든 값을 그대로 사용하며 일반 비밀번호로 바꾸거나 변환하지 않습니다.
3. 필요하면 **장비 Pan·Tilt·Zoom 함께 조회**를 체크하고 **JPEG 연결 시험·수신 시작**을 누릅니다.
   인증값이 포함된 주소 입력란은 성공·실패 모두 지웁니다. 각도 조회는 기본으로 꺼져 있습니다.
4. 영상 장수와 수신 시각의 갱신을 확인하고 **직접 연결 종료**로 중지합니다.

전체 요청 주소는 인증값을 포함하므로 프로그램의 가려진 로컬 입력란에만 붙여넣습니다.
요청은 localhost POST 본문으로 전달하며 연결 중 메모리에만 유지합니다. 지도 JSON·참조 이미지·
상태 응답·로그·배포 패키지에 주소나 인증값을 넣지 않습니다. 오류에 원본 URL을 표시하지 않습니다.
JPEG에는 인증 쿠키를 보내지 않으며 HTTP 인증 폴백·리디렉션과 다른 조회 경로를 시도하지 않습니다.
반복 JPEG 요청마다 웹뷰어의 `time` 캐시 방지 값만 갱신합니다.

### NVT Position OSD 현재 PTZ 조회

사용자가 제공한 `positionOSD.html`의 `updatePanPosition()`에서 다음 GET을 확인했습니다.

`/api/ptz.cgi?PTZNumber=1&GetPTZPosition=do`

각도 조회를 켠 연결에서만 같은 장비의 같은 scheme/host/port에 약 1초마다 이 요청을 보냅니다.
웹뷰어와 같은 이름의 `username`·`password` 쿠키는 입력한 JPEG 주소의 USER·PWD를 URI 인코딩해
이 상태 요청 한 개에만 붙입니다. 쿠키 저장소·다른 장비·JPEG 요청·주소 이동에 재사용하지 않습니다.
`/api/ptz.cgi`는 이동 명령도 받으므로 경로와 전체 쿼리를 고정하며 제어 인자는 허용하지 않습니다.

`PTZ.1.Position=Pan,Tilt,Zoom` 형태에서 유한한 세 값과 범위를 확인합니다.
Pan만 돌아오는 응답에 Tilt·Zoom을 임의로 채우지 않습니다. 0도는 유효하며 Zoom은 양수여야 합니다.
NVT 응답에 없는 ZoomPulse는 null로 표시하고 0으로 만들지 않습니다.
오류·누락·권한 거절·타임아웃이면 각도 조회를 멈추고 JPEG 수신은 계속합니다.
세 값이 유효할 때 기존 **장비 PTZ 근사 추종**, 카메라별 기준 저장·재개와 **영상·PTZ 기준 묶음 저장**에 사용할 수 있습니다.
묶음에는 NVT 영상 출처와 InputNumber만 기록하며 접속 주소·인증값·쿠키는 넣지 않습니다.
각도의 지리적 방향, 기울기 변화 방향과 줌 화각 근사는 현장 기준으로 확인해야 합니다.

## 기존 지도에서 설치 좌표 수정

새 패키지를 별도 폴더에서 실행하면 이전 폴더의 지도 설정이 자동으로 이동하지 않습니다.
이전 프로그램의 **좌표 설정 다운로드**로 보관한 JSON을 새 프로그램에서 불러오거나,
프로그램을 종료한 상태에서 이전 `data/map.demo.json`을 새 폴더의 같은 위치로 복사합니다.

**카메라·설정 → 대상 카메라 → 선택 카메라 설치 좌표 수정**에서 위도·경도를 바꿀 수 있습니다.
족두리봉의 사용자 수정 좌표는 **37.61785 / 126.94291 (WGS84)**입니다.
기존 좌표가 남아 있으면 **족두리봉 수정 좌표 적용** 버튼으로 이 값만 적용합니다.
보현봉의 사용자 수정 좌표는 **37.62838 / 126.97420 (WGS84)**이며,
기존 설정에는 **보현봉 수정 좌표 적용** 버튼으로 반영합니다.
이전 실행패키지에서도 위도·경도를 직접 입력한 뒤 **설치 좌표 수정 적용**을 누를 수 있습니다.
선택 카메라의 ID·이름과 다른 카메라의 저장 기준은 유지합니다.
위치에 묶인 해당 카메라의 이전 방향·PTZ 기준은 제거하므로 새 설치 위치에서 다시 잡습니다.
마지막에 **중앙 지도 설정 저장**(로컬 저장 키 `local-demo-only`) 또는 JSON 다운로드로 보관합니다.

## 실행이 안 될 때

- 압축을 모두 풀었는지, exe와 wwwroot 및 나머지 DLL 파일이 같은 폴더에 있는지 확인하세요.
- 브라우저가 열리지 않으면 콘솔의 Browser 주소로 직접 접속하세요.
- 오류 창이 바로 닫히면 `문제진단.cmd`를 실행해 오류를 확인하세요.
- 저장 오류는 압축을 푼 폴더의 쓰기 권한을 확인하세요. 기존 파일을 삭제할 필요는 없습니다.
- 회사 보안 정책이 실행을 차단하면 담당자에게 확인하세요. 이 패키지는 코드 서명되지 않았습니다.

검증 범위: Linux 빌드 환경에서 Windows x64 self-contained publish 및 ZIP 무결성 검증.
공통 웹/Bridge와 로컬 시연 시작·저장 경로를 테스트합니다. 2026-10-14 사용자 회사 PC에서 백운대 영상의 캡처 도구 표시와 로컬 브라우저 지속 갱신을 확인했습니다. 다른 환경과 새 지도 패널의 현장 확인은 별도입니다.

## 지도 시험

지도 모니터링 탭에서 북한산 임의 시험 좌표를 확인합니다. 키 없이 좌표 배치도를 볼 수 있습니다.
VWorld 3D를 보려면 인터넷 연결과 이 앱 주소를 허용하는 VWorld 키가 필요합니다.
키를 입력하고 연결하세요. 기존 GitHub Pages 등록 키가 로컬 주소에서도 작동한다고 보장할 수 없습니다.
좌표와 추정 방향은 `중앙 지도 설정 저장`에서 local-demo-only 키로 저장하며 data/map.demo.json에 보관합니다.
다시 실행하면 불러오고, JSON 다운로드/입력도 가능합니다. 영상·지형 보정은 촬영 시각과 기준점 두 곳 이상을 기록합니다.
정확도 미검증 추정이며 지리적 현재 방향은 UNKNOWN입니다. 직접 수신의 원시 장비 PTZ와 구분합니다. 상세: docs/terrain-calibration.md.
자세한 내용: docs/vworld-monitoring.md, docs/video-direction-feasibility.md.

## 실제 장치 리포트 가져오기

카메라 목록 탭에서 SSM 장치 설정 리포트(.xls)를 선택하면 이름/Guid/모델/PTZ 표시를 미리 볼 수 있습니다.

정규화 목록은 demo/inventory.json에 보관하고 재시작해도 유지합니다. 실제 SSM 연결은 없습니다.
배포 ZIP에는 실장비 데이터가 없으며 리포트는 직접 불러옵니다. 상세: docs/ssm-report-import.md.
