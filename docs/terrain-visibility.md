# 지형 가시권과 사찰 감시

기존 카메라 선택 화면 옆 **지형·사찰 가시권** 탭을 추가했습니다. 실시간 영상이나 SSM 없이도 기존 위치 JSON과 DEM을 불러와 분석할 수 있습니다. 사찰 좌표가 아직 없어도 카메라의 전체 지형 가시권을 계산합니다. 브라우저 Web Worker에서 계산하며 카메라 제어 명령이나 중앙 설정 쓰기 요청은 보내지 않습니다.

## 시작하기

```sh
cd web
npm ci
npm run dev
```

화면에서 **지형·사찰 가시권 → 가상 지형 예제 열기**를 선택하면 능선 앞/뒤의 합성 사찰 두 곳을 볼 수 있습니다. 예제는 실제 지형·사찰·카메라 데이터가 아닙니다. API가 없어도 이 탭의 파일 분석은 작동하며, 기존 카메라 선택 탭은 Bridge 연결이 필요합니다.

1. 기존 카메라 JSON을 **카메라 JSON**에서 불러옵니다. Bridge를 사용 중이면 **중앙 설정 카메라 불러오기**로 `/api/cameras`의 설정을 읽을 수 있습니다.
2. 각 카메라의 지상 설치 높이와 최대 감시 거리를 확인하거나 입력합니다. 입력하지 않으면 해당 카메라는 데이터 부족으로 남습니다.
3. **지형 DEM JSON**에서 대상 지역의 고도 격자를 불러옵니다. 카메라부터 대상까지의 경로 전체를 포함하는 DEM이 필요합니다.
4. 좌표 취합이 끝나면 **사찰 JSON**을 불러옵니다. 사찰명을 클릭하면 카메라별 감시 상태와 주변 반경을 확인합니다.
5. **분석 입력 저장**으로 보관하고 **결과 GeoJSON 저장**으로 GIS에서 사용할 결과를 받습니다. 브라우저를 닫거나 새로고침하면 입력이 사라집니다. 기능 탭 사이를 전환할 때는 입력을 유지합니다. 파일은 브라우저 밖으로 전송하지 않습니다.

개별 파일 불러오기는 같은 종류의 목록을 교체합니다. 오류가 있으면 기존 입력을 유지합니다. 가상 예제에 실제 파일을 부분적으로 섞으면 가상 데이터 표시는 유지됩니다. 실제 분석으로 전환하려면 새로고침 후 개별 실제 파일들을 불러오거나, 실제 자료만 담은 `synthetic: false` 통합 JSON을 불러옵니다.

## 기존 카메라 JSON

기존 `config/cameras.example.json`의 `cameras` 배열과 좌표 필드를 그대로 사용합니다. 분석에 필요한 필드만 읽으므로 기존 장치 정보는 원본 JSON에 보관하세요. **분석 입력 저장은 분석용 필드만 내보내며 중앙 카메라 설정 파일의 대체물이 아닙니다.** 좌표가 null인 카메라가 있으면 먼저 위치를 채우거나 해당 레코드를 파일에서 제외해야 합니다. 최대 32대입니다.

```json
{
  "cameras": [{
    "uuid": "existing-camera-uuid",
    "name": "카메라 이름",
    "latitude": 37.005,
    "longitude": 127.005,
    "enabled": true,
    "groundElevationM": null,
    "cameraHeightM": 15,
    "rangeM": 5000,
    "headingDeg": 90,
    "horizontalFovDeg": 60,
    "tiltDeg": -5,
    "verticalFovDeg": 40
  }]
}
```

위 좌표·설정은 형식 설명용입니다. 실제 설치 기록과 광학 사양으로 대체하세요.

- `cameraHeightM`: 지면에서 카메라 광학 중심까지 높이(m). 해발 고도가 아닙니다.
- `groundElevationM`: 설치 지반 해발 고도(m). null이면 DEM에서 추출합니다. DEM과 동일한 수직 기준을 사용해야 합니다.
- `rangeM`: 유효 감시 거리(m), 1~50,000. 거리 내라고 화재를 식별할 수 있음이 보장되지는 않습니다.
- `headingDeg`: 실제 북쪽 0°, 동쪽 90°, 시계 방향 방위각. 기존 `headingOffsetDeg`는 보정값이므로 실제 방향으로 해석하지 않습니다.
- `horizontalFovDeg`: 수평 시야각. 생략 또는 360이면 360° 회전 시 잠재 감시 범위입니다. 고정 카메라의 현재 화면으로 해석하면 안 됩니다. 360 미만이면 `headingDeg`가 필요합니다.
- `tiltDeg`: 수평 0°, 위쪽 양수, 아래쪽 음수. `verticalFovDeg`를 설정하면 함께 입력합니다. 기존 정규화 PTZ 값이나 `tiltOffsetDeg`를 직접 사용하지 않습니다.
- `enabled: false`: 분석에서 제외합니다.

## 지도 위치 파일 (`camera-map-positions*.json`)

**카메라 JSON** 입력에서 `schemaVersion: 1`, `crs: "EPSG:4326"`, `positions` 배열의 기존 지도 저장 파일도 직접 읽습니다. `lat/lon`은 위도/경도로, `id`는 지도 위치 ID로 가져옵니다. `ssmUuid`가 없으면 `map-position:<id>`라는 분석 내부 키를 사용하며, 이를 실제 SSM UUID로 간주하지 않습니다.

설치 높이·지반 고도는 현재 좌표와 `positionAtCalibration`이 일치하는 `nativeTracking.pose.cameraHeightM` / `nativeTracking.groundElevationM`에서 읽고, 없거나 위치가 다르면 일치하는 `orientation`을 확인합니다. 둘 다 위치가 다르거나 보정 위치가 없으면 높이·지반 고도를 사용하지 않습니다. 좌표 일치 허용 오차는 각 축 0.0000001도입니다. 신뢰도와 보정 시각을 함께 표시합니다.

기본 분석은 **360° 회전 잠재 가시권**입니다. 카메라별 **저장 수평 시야 사용** 버튼을 누르면 해당 보정값의 `headingDeg`와 `horizontalFovDeg`만 적용합니다. 저장 시점의 추정 수평 시야이며 현재 화면이 아닙니다. 수직 시야각이 없고 원본 pitch의 좌표계가 확정되지 않았으므로 `pitchDeg`와 `deviceAnchor`의 pan/tilt/zoom으로 현재 수직 시야나 줌을 추정하지 않습니다. 최대 감시 거리 `rangeM`이 없으면 화면에서 입력해야 하며, 기본 거리를 임의 지정하지 않습니다.

분석 입력 내보내기는 원본 지도 파일의 `orientation.landmarks`나 `nativeTracking.deviceAnchor` 등 전체 메타데이터를 보존하지 않습니다. 원본 파일은 별도로 보관하세요. 업로드한 실제 카메라 위치 파일은 소스 저장소의 예제에 포함하지 않습니다.

## 사찰 JSON

```json
{
  "temples": [{
    "id": "temple-001",
    "name": "사찰 이름",
    "latitude": 37.006,
    "longitude": 127.006,
    "targetHeightM": 0,
    "radiusM": 300
  }]
}
```

좌표는 WGS84 경위도입니다. `targetHeightM`은 사찰 좌표에서 감시하려는 지상 높이(m), 기본 0입니다. `radiusM`은 사찰 주변 지상 감시를 요약할 반경(m), 기본 0입니다. 사찰 한 점의 가시성은 사찰 부지 전체의 가시성을 뜻하지 않습니다. 최대 500곳이며, ID는 중복될 수 없습니다. 사찰 부지 폴리곤 분석은 아직 포함하지 않습니다.

## DEM JSON 및 GeoTIFF 변환

```json
{
  "source": "DEM 제공기관 / 취득시점 / 원 해상도 / 수직 기준",
  "west": 127.0,
  "south": 37.0,
  "east": 127.01,
  "north": 37.01,
  "elevations": [[100, 100, 100], [100, 200, 100], [100, 100, 100]]
}
```

행은 **북→남**, 열은 **서→동** 순서의 **격자 절점** 고도(m)입니다. 첫 절점은 `(west,north)`, 마지막 절점은 `(east,south)`입니다. 2~256행/열의 직사각 배열이며, 결측은 `null`입니다. 0은 실제 해발 0m이므로 결측에 사용하면 안 됩니다. 범위는 각 축 최대 1도입니다. 카메라와 DEM의 높이 단위 및 수직 기준을 맞춰야 합니다.

이미 확보한 GeoTIFF DEM은 변환 유틸리티로 불러올 수 있습니다. 이 스크립트는 지형 데이터를 다운로드하지 않습니다.

```sh
python -m pip install rasterio numpy
python scripts/dem-to-json.py dem.tif terrain.json \
  --source "제공기관 / 날짜 / 원 해상도 / 수직 기준" \
  --bounds 127.0 37.0 127.04 37.03 --size 128
```

`--bounds`는 서·남·동·북 경계이며 선택 사항입니다. 없으면 원본 경계를 WGS84로 변환합니다. EPSG:4326으로 재투영해 격자 절점 위치에서 고도를 보간하고 결측은 null로 유지합니다. 광역 DEM은 미리 대상 지역으로 자르는 것이 좋습니다. 수평 좌표만 재투영하며 수직 기준·단위는 변환하지 않습니다. 원본의 band scale/offset은 반영합니다.

통합 JSON은 `{ "label": "분석명", "synthetic": false, "terrain": {...}, "cameras": [...], "temples": [...] }` 형식입니다. 입력 파일당 최대 8MB입니다.

## 계산과 결과 해석

- DEM 고도는 쌍선형 보간합니다. 카메라 광학 중심에서 대상까지 직선을 따라 격자 간격의 1/4 이하로 표본을 잡고 지형이 시선보다 높으면 가림으로 판정합니다. 표본 기반 근사이므로 격자 사이의 매우 좁은 장애물을 놓칠 수 있습니다.
- 지구 곡률(반지름 6,371,008.8m)을 반영합니다. 대기 굴절은 반영하지 않습니다. 지역 범위의 경위도 직선 보간을 사용하며 정밀 측량용 계산은 아닙니다.
- 전체 지도는 64×64 격자의 **중심점**마다 지상 0m 대상을 평가합니다. GeoJSON 폴리곤의 색은 해당 격자 중심점의 결과이며 폴리곤 내부 모든 점에 대한 보장이 아닙니다. 원 DEM을 조밀하게 재표본화해도 실제 해상도는 개선되지 않습니다.
- 여러 활성 카메라 중 하나라도 볼 수 있으면 녹색 **감시 가능**입니다.
- 감시 가능 카메라가 없고 미확인 카메라가 남아 있으면 회색 **데이터 부족**입니다. 카메라가 없거나 전부 비활성인 경우도 같습니다.
- 미확인 없이 지형에 가리는 카메라가 있으면 빨강 **지형 가림**입니다. 모든 카메라의 거리·시야 밖이면 황색 **거리·시야 밖**입니다.
- 경로에 DEM 결측이 있으면 데이터 부족입니다. 다만 알려진 지형 장애물이 확인되면 그 경로는 가림으로 확정할 수 있습니다. 이미 알려진 거리·시야 밖 조건도 별도로 판정합니다.
- 사찰 주변 사각지대 비율은 반경 안의 격자 중심점 중 빨강+황색의 비율입니다. 회색 비율을 별도로 표시합니다. DEM 밖인 반경 부분은 집계하지 않으며 화면에 부분 집계라고 표시합니다. 작은 반경에 격자 중심점이 없으면 표본 없음으로 표시합니다. 정확한 면적 비율이 아닙니다.
- SVG 경위도 격자 지도와 고도 레이어를 제공합니다. 배경 도로·위성 지도, VWorld 3D 지형, 실시간 PTZ 구독은 아직 연결하지 않았습니다.
- GeoJSON에는 분석 출처·합성 여부·입력 카메라·생성 시각·격자 상태와 사찰별 카메라 판정을 포함합니다. 녹색은 기하학적 가시성 추정이며 영상 식별·화재 탐지 성능 검증이 아닙니다. 수목·건물이 필요하면 해당 장애물이 포함된 DSM과 실제 시야 검증을 함께 사용하세요.

## 검증

```sh
cd web
npm run build
npx playwright install chromium
npm run test:visibility
```

가상 평지·능선·높은 대상, 다중 카메라, 거리·수평/수직 시야, 결측과 범위 밖, 곡률, JSON 검증을 계산 테스트로 확인합니다. UI 테스트는 예제·파일 입력·설치 높이 보완·사각지대 필터·사찰 상세·GeoJSON·모바일 화면을 확인합니다. 기존 Bridge 통합 테스트는 .NET 8이 있는 환경에서 기존 절차대로 실행합니다.
