# 로그인 전 WebViewer 인증 방식 확인

회사 PC의 사용자 화면에서 **Hanwha Vision WebViewer** 제목, `/wmf/index.html#/login` 주소와
브라우저 인증 창을 확인했습니다. 등록 HTTP origin에 해당하는 화면이 관측됐습니다.
모델/MAC/시리얼, 실제 인증 응답 코드 및 인증 방식은 사진에 표시되지 않습니다.
이 화면만으로 선택한 백운대 장비와의 일치나 현재 PTZ 지원을 확정하지 않습니다.

브라우저의 기본 로그인 팝업은 Basic/Digest 등에서 비슷하게 보입니다. HTTP의 ‘안전하지 않음’ 표시도
인증 방식을 구분하는 근거가 아닙니다. 인증 창을 띄운 요청이 HTML 문서인지 웹앱의 추가 요청인지
사진에서 알 수 없으므로, 추측한 API를 보내거나 문서 경로의 응답으로 대신 판단하지 않습니다.
`#/login`은 브라우저 안에서 사용하는 fragment이며 HTTP 요청 경로 `/login`을 뜻하지 않습니다.

## 회사 PC에서 확인

사용자는 카메라 장비 계정을 모른다고 답했습니다. 현재는 [SSM 계정 기반 CONTROL 조사](ptz-investigation-decision.md)를
우선하며 아래 F12 작업은 보조 조사입니다. 이 작업을 완료해야 SSM 진단 v4를 실행할 수 있는 것은 아닙니다.

이 단계에는 로그인·계정 입력·새 프로그램 설치가 필요하지 않습니다.

1. 현재 인증 팝업의 **취소**를 누릅니다.
2. **F12** 또는 **Ctrl+Shift+I**로 개발자 도구를 열고 **네트워크(Network)** 탭을 선택합니다.
3. 페이지를 한 번 새로고침합니다. 인증 팝업이 다시 뜨면 **취소**합니다.
4. 네트워크 목록에서 **상태(Status) 401**인 요청을 선택합니다.
   필터 칸에 `status-code:401`을 입력하면 해당 응답을 좁힐 수 있습니다.
5. **헤더(Headers) → 응답 헤더(Response Headers) → WWW-Authenticate**를 봅니다.
   표시된 인증 방식의 **Basic/Digest 같은 이름만** 알려주세요. 여러 방식이면 이름을 모두 적습니다.

401 요청이 없거나 헤더가 보이지 않으면 그 사실을 알려주세요. 인증 방식을 임의로 Basic/Digest라고
정하지 않고 실제 기록을 추가 확인합니다. 단순 접속 성공과 현재 위치 조회 성공도 구분합니다.

비밀번호·Cookie·Authorization·realm/nonce 및 전체 헤더는 필요하지 않습니다.
**HAR 내보내기나 전체 네트워크 기록 공유는 요청하지 않습니다.** 로그인하지 않은 상태에서 응답 헤더의
방식 이름만 확인하고, 설치 설정·계정·ONVIF·PTZ 조작권은 변경하지 않습니다.

## 이후 판단

- Digest 관측: 해당 응답에서 Digest를 제공한다는 근거입니다. 장비 계정, 모델/MAC 등 대상 매핑과
  공식 SUNAPI 현재 위치 계약 또는 실제 ONVIF 서비스 정보를 확보한 뒤 제한된 읽기 시험을 진행합니다.
- Basic 관측: 이 HTTP 응답의 Basic 제공 사실을 기록합니다. 준비된 ONVIF 도구는 Basic을 전송하지 않습니다.
  HTTPS 경로 또는 별도로 확인된 Digest/CONTROL 경로를 조사하며 다른 포트나 암호를 자동 시험하지 않습니다.
- 모델과 고유 장비 식별정보는 아직 미확인입니다. 같은 모델의 여러 카메라가 있으므로 브랜드/모델만으로
  SSM UUID와 장비 매핑을 검증했다고 처리하지 않습니다.

SSM 계정과 카메라 장비 계정은 다를 수 있습니다. ID·비밀번호는 채팅/GitHub로 받지 않습니다.
이번 확인에서 인증 요청·HTTP 응답을 관찰하는 것과 SUNAPI/ONVIF 현재 PTZ를 직접 요청하는 것은 별개입니다.
