# 아이폰에서 FIREWATCHER 문자 전달하기

검토일: 2026-10-30, 한국시간. 사용자는 온라인 수신번호 조사를 보류하고 아이폰 자동전달 경로를 먼저 확인하도록 요청했다.
이 문서는 전달 경로와 수동 설정 절차를 정리한 것이다. 아이폰을 원격으로 설정하거나 문자를 발송하지 않았고, 사용자 아이폰에서 실제 수신·잠금 상태 전송을 검증하지 않았다.

## 권장 경로: 아이폰에서 본인 메일함으로 전달

**FIREWATCHER 문자 수신 → 아이폰 단축어 → 본인 전용 메일함 → 개인 PC의 프로그램에서 메일 조회 → 알림 링크의 정보 확인 → 지도 알림 표시**

아이폰과 개인 PC가 같은 네트워크에 있거나 회사 VPN을 함께 사용할 필요가 없다.
메일함에 성공적으로 도착한 알림은 PC 종료 중에도 보관할 수 있고, 프로그램을 켰을 때 미처리 메일을 읽도록 구현할 수 있다.
메일 도착 시간과 프로그램 조회 주기에 따른 지연은 생길 수 있다.

**현재 프로그램에는 SMS 수신 API와 메일 수신 어댑터가 없다.** 아래 아이폰 설정은 메일 전달을 준비하는 단계이며, 현재 버전의 AI 메뉴에 자동으로 표시되지는 않는다.
알림 페이지의 HTML/API 계약도 아직 확인하지 못했으므로 카메라명·이미지를 읽는 어댑터는 실제 응답 확인 후 작성해야 한다.

## 준비할 것

- 일반 문자를 정상 수신하는 사용자의 아이폰과 인터넷 연결.
- 메시지 개인용 자동화에서 즉시 실행을 설정할 수 있는 iOS 버전. 아래 절차는 iOS 17 이상을 기준으로 하며 실제 메뉴와 동작은 사용자 기기에서 확인한다.
- 아이폰 기본 **Mail(메일)** 앱에 등록되어 정상 발신할 수 있는 계정.
- 사용자가 관리하는 알림 전용 메일함 또는 분리된 폴더. 송신 계정과 수신 계정을 반드시 다르게 만들 필요는 없다.
- PC에서 해당 메일함을 읽을 수 있는 공식 API 또는 IMAP 설정. 인증 방식은 메일 서비스에 따라 결정하며 비밀번호를 채팅에 공유하지 않는다.

기본 Mail 앱 계정 등록과 자동화 설정은 아이폰에서 최초 한 번 진행한다. Windows 실행파일이 아이폰 개인용 자동화를 대신 설치하지는 않는다.

## 아이폰 설정 순서

1. 기본 **메일** 앱에서 사용할 계정으로 본인 수신함에 메일을 보낼 수 있는지 확인한다.
2. **단축어 → 자동화 → + → 메시지**를 선택한다.
3. **발신자**에는 실제 FIREWATCHER 문자 대화에서 확인한 번호를 선택한다. 번호가 연락처 선택으로만 표시되면 해당 번호를 연락처로 저장해 선택한다. 캡처의 번호를 OCR로 추측해 입력하지 않는다.
4. **메시지 포함**에는 `/sms/`를 입력한다. 발신자 조건도 함께 사용해 해당 시스템의 알림 링크가 담긴 문자로 범위를 제한한다.
5. **즉시 실행**을 선택한다. iOS 버전에 따라 메뉴 배치·명칭이 다를 수 있다. 처음 사용하는 메일·개인정보 접근 동작은 권한 확인이 필요할 수 있다.
6. 동작 **텍스트**를 추가하고, 수신된 메시지의 **단축어 입력 → 내용** 또는 텍스트 속성을 변수로 선택한다. `단축어 입력`이라는 글자를 직접 타이핑하지 않는다. 실제 문자 본문 전체가 들어가야 한다.
7. **메일 보내기** 동작을 추가한다.
   - 받는 사람: 사용자가 관리하는 알림 수신 메일함.
   - 제목: `[FIREWATCHER]`.
   - 본문: 앞 단계의 텍스트 변수 전체.
   - 보내는 계정: 기본 Mail 앱에 설정한 계정.
   - 세부 옵션의 **작성 화면 표시 / 작성 시트 표시(Show Compose Sheet)**: 끔.
8. 처음에는 자동화 실행 알림을 켜 두고 저장한다.

문자 내용을 가공하거나 URL을 줄이지 않는다. 링크의 경로 조각을 카메라 ID·이벤트 ID로 임의 해석하지 않는다.
전화기에서 기록하는 전달 시각과 원본 시스템의 감지 시각은 구분한다.

## 최소 확인 순서

1. 사용자가 직접 실행한 단축어에서 테스트 텍스트가 본인 메일함에 도착하는지 확인한다. 이 시험은 메시지 수신 트리거의 동작까지 증명하지는 않는다.
2. 실제 다음 FIREWATCHER 문자 한 건으로, 아이폰이 잠겨 있는 상태에서도 자동화가 실행되고 전체 링크가 메일에 도착하는지 확인한다.
3. PC를 종료한 동안 메일함에 도착한 알림이 남아 있는지 확인한다. PC의 미처리 알림 조회는 프로그램의 메일 수신 기능 구현 후 확인한다.

자동화는 새로 수신한 메시지를 대상으로 한다. 이전 문자 대화를 자동으로 소급해서 읽는 기능으로 간주하지 않는다.
아이폰이 꺼져 있거나 통신·메일 전송이 실패하면 메일함에 도착했다고 볼 수 없다. 단축어의 실패 요청에 자동 재전송·내구성 있는 대기열이 기본 제공된다고 가정하지 않는다.
PC가 꺼져 있어도 보관되는 것은 메일함에 이미 성공적으로 전달된 알림이다.
메일의 보관 기간과 FIREWATCHER 링크의 유효기간은 별개다. 오래된 링크의 페이지·이미지가 계속 제공된다고 가정하지 않는다.

## 대안: 아이폰에서 개인 PC로 직접 HTTPS 전달

**문자 수신 → 단축어 ‘URL의 콘텐츠 가져오기’ → 인증된 수신 API → 프로그램**으로 구성할 수도 있다.
공개 구현 자료에서 메시지 본문 변수를 JSON POST로 전달하는 구성을 확인했다.

그러나 현재 앱은 루프백 주소에 바인딩되어 있고 모니터링 로그인 세션을 요구한다.
아이폰의 `127.0.0.1`은 개인 PC 주소가 아니며, 기존 지도 저장 API를 문자 수신용으로 사용할 수 없다.
다음 작업이 추가로 필요하다.

- 프로그램의 별도 문자 수신 API와 제한된 수신용 인증키.
- 아이폰에서 접근 가능한 HTTPS 경로. 기존 문서의 VPN/Tailscale Serve 같은 경로를 사용할 수 있으나 아직 사용자 PC에 구성되었다고 확인하지 않았다.
- 수신 시 PC와 프로그램이 실행 중이어야 한다. 실패 시 재전달과 PC 종료 중 보관을 별도로 설계해야 한다.

| 항목 | 메일함을 거치는 방식 | 개인 PC로 직접 전달 |
| --- | --- | --- |
| PC의 공개 수신 주소 | 필요 없음. 프로그램에서 메일 서비스로 조회 | 아이폰에서 접근 가능한 HTTPS 경로 필요 |
| PC 종료 중 | 메일함에 성공적으로 도착한 알림 보관 | 별도 보관·재전달 없이는 수신 불가 |
| 전달 지연 | 메일 전송과 조회 주기에 영향받음 | 수신 API에 직접 전달 |
| 프로그램 추가 기능 | 메일 조회·중복 처리·알림 해석 | 인증된 수신 API·중복 처리·알림 해석 |

## 다음 구현에서 지킬 경계

- 대상 발신자·제목·알림 서버가 일치하는 자료만 읽고, 다른 개인 문자를 일괄 수집하지 않는다.
- 수신함 읽기와 FIREWATCHER 알림 해제·삭제를 연결하지 않는다.
- 본문과 원본 링크의 접근용 경로 값은 공개 소스·로그·빌드에 넣지 않는다.
- 원본 감지 시각, 문자/메일 수신 시각, 프로그램 처리 시각을 분리한다.
- 실제 페이지 응답에서 확인된 카메라를 지도 카메라에 연결한다. 과거 감지에 현재 PTZ를 자동 적용하지 않는다.
- 기존 9대 보정값과 카메라 접속 설정은 이 경로 조사로 변경하지 않는다.

이것은 사용자 아이폰에서의 무인 동작이나 국내 발신 문자 수신 성공을 검증한 결과가 아니다. 사용자 기기의 메뉴와 실제 문자 한 건으로 확인해야 한다.
